# 📝 Contribution Guidelines

## Git Workflow for the Hackathon

1. **Initialize Repo:** `git init` and push to a **public** GitHub repo immediately.
2. **Branch Naming:** Use `main` as the primary branch. No need for feature branches – keep it simple.
3. **Commit Messages:** Follow this format:
   - `feat: add user authentication`
   - `fix: resolve API timeout issue`
   - `docs: update architecture diagram`
   - `style: polish UI animations`
4. **Commit Frequency:** Commit at least every 30–60 minutes to show steady progress.
5. **Pull Requests:** Use PRs for merging code between members. Keep them small and focused.
6. **README Updates:** Update this file whenever tech stack, architecture, or features change.
7. **Code Understanding:** Every team member must be able to explain any part of the codebase. No "magic code."

## 🚫 AI Rules
- You may use AI for **references, debugging, explanations, and individual snippets**.
- You may **NOT** use Cursor, Lovable, Replit AI builders, or autonomous coding agents to substantially build the project.
- All code must be understood by the team for live evaluation Q&A.
